## Summary

Stack: NestJS. Adds a RAG backend: document ingestion (text + PDF upload), recursive chunker, OpenAI-compatible embeddings, Chroma/in-memory vector stores, and /ask (plain + SSE streaming) with history-aware query rewriting. Global throttling, ValidationPipe and CORS are wired in main.ts/app.module.ts. Code is well structured and tested; main concerns are missing auth on destructive/cost-bearing endpoints, unbounded full-collection reads, and unversioned routes.

### High (3)
- **src/documents/documents.controller.ts:639** — No authentication/authorization on any endpoint: anyone can upload/index documents (paid embeddings), call /ask (paid LLM calls), list, rename and delete every document. Documents are global, not scoped to an owner, so any caller can read or delete any other caller's data (IDOR). Throttling is the only protection. *(security)*
  - status: skipped
  - dev_reasoning: Intentionally unauthenticated: this is an internal, single-tenant tool used only by our own team, so per-user auth and document ownership are not needed.
  - ai_reasoning: Still open: only ThrottlerGuard is registered and no ownerId scoping exists. Add a global auth guard (APP_GUARD + @Public() opt-outs) and store an ownerId in chunk metadata, scoping list/search/ask/rename/delete by the current user. If this is intentionally a single-tenant internal tool, record that via skip with a reason.
- **src/vector-store/chroma-vector-store.service.ts:1148** — list() fetches every chunk in the collection including embeddings and text with no limit, and is used by GET /documents (list) and by renameDocument just to check existence/aggregate counts. Cost and memory grow linearly with the whole corpus on each call. *(performance)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Fetch only metadatas (drop 'embeddings' and 'documents' from include), page with limit/offset, and for the rename existence check use collection.get({ where: { documentId }, limit: 1 }) instead of listing everything.
- **src/main.ts:11** — Routes are unversioned: no global prefix or URI versioning, so endpoints are /ask, /documents, etc. rather than /api/v1/.... *(consistency)*
  - status: fixed
  - dev_reasoning: N/A
  - ai_reasoning: Add app.setGlobalPrefix('api') with enableVersioning({ type: VersioningType.URI, defaultVersion: '1' }) (or v1 controller paths) and update the frontend base URL accordingly.
